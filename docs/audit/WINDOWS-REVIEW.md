# Windows platform review

Reviewed 2026-10-11 against current Microsoft primary documentation and the 0.2.0 candidate source. This is an API/design review, not a claim that every Windows integration has passed desktop testing. See [ACCEPTANCE.md](ACCEPTANCE.md) for test gates.

## Source refresh — 2026-10-12

- Microsoft Learn currently lists .NET 10 as LTS through November 2028, and .NET 8/.NET 9 through November 2026. The product remains on .NET 10 for support lifetime and updateability, not because runtime migration alone proves better speed. For a consumer app, self-contained deployment removes a runtime-install requirement but makes the publisher responsible for rebuilding/releasing runtime servicing updates. [Releases and support](https://learn.microsoft.com/dotnet/core/releases-and-support), [Microsoft lifecycle dates](https://learn.microsoft.com/en-ie/lifecycle/products/microsoft-net-and-net-core).
- Current WPF deployment guidance still supports self-contained distribution for an app that should run without client runtime installation; it does not give portable bundles installer-style versioning, uninstall or rollback. This supports the current simple portable EXE, while leaving installer tradeoffs explicit. [Deploy a WPF app](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/app-development/deploying-a-wpf-application-wpf).
- The DPI guidance stresses that system-DPI awareness can become blurry when moved between differently scaled displays; high-contrast mode is not a substitute for readable default contrast. Our manifest/resources must therefore be confirmed with actual mixed-DPI and High Contrast runs, not inferred from WPF or manifest declarations. [High-DPI desktop development](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows), [accessible text requirements](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements).
- Host check: Windows build 26200 x64; system runtimes are only .NET 8.0.31 and SDK is 8.0.425. The exact .NET 10 self-contained candidate remained up for the full 601.69-second isolated desktop-QA idle run. This shows it does not require an installed .NET 10 runtime; it does **not** prove behavior on a clean machine without any SDK/runtime. See `ACCEPTANCE.md` for measured counters and the bounded claim.

## Decisions, evidence and remaining verification

| Area | Official contract and implementation decision | Cost / alternative | Verification boundary |
| --- | --- | --- | --- |
| Supported runtime | .NET 10 is active LTS through 2028-11-14; .NET 8 support ends 2026-11-10. Use SDK 10.0.401, runtime 10.0.12, `net10.0-windows`, patch selection in `global.json`. [Support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) | No framework rewrite; bundled runtime increases distribution size. Self-contained copies need rebuilt releases for runtime fixes. | SDK/build verified locally. No claim of Windows 10 or native ARM64 support. |
| WPF versus new UI stack | WPF remains maintained; .NET 10 changes clipboard internals shared with WinForms. Keep native WPF/Win32; no requirement to introduce Windows App SDK or WinUI for this scope. [WPF .NET 10 changes](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100) | Migration retains controls, accessibility peers and small dependency surface. Custom control templates still require theme/accessibility tests. | Compilation cannot prove inter-process text/image/files compatibility after runtime migration. |
| Clipboard notifications | `AddClipboardFormatListener` delivers `WM_CLIPBOARDUPDATE`; check registration and unregister on shutdown. Keep event-driven capture, sequence checks and bounded retries; no permanent polling. [Listener API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener) | One pending/latest capture and bounded image work avoid an unbounded event queue. Intermediate rapid clipboard states may be superseded; this is not a lossless event recorder. | Native registration, busy clipboard, bursts and shutdown need final-binary tests beyond unit checks. |
| Privacy formats | Presence of `ExcludeClipboardContentFromMonitorProcessing` is an opt-out. `CanIncludeInClipboardHistory` and `CanUploadToCloudClipboard` use serialized DWORDs. Capture fails closed on an invalid explicit history marker; replay publishes payload and both zero-valued markers together. [Clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats) | Small bounded helper; no arbitrary object deserialization. Cloud-only opt-out does not by itself prohibit local history, as these policies have distinct meanings. | In-memory STA marker tests passed; cross-process marker/payload replay still requires final desktop acceptance. Third-party applications may ignore these hints. |
| Hotkeys | Reserve a new hotkey before releasing the old one, use `MOD_NOREPEAT`, handle conflicts and release registrations. F12 is reserved for debugging even without a debugger; Windows-key combinations are OS-reserved. [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) | Existing Win32 API is sufficient. The picker, display/help text and storage validation now agree on Ctrl/Alt with letters, digits or F1–F11. | Resume review found F12 still allowed; corrected before freeze and covered by validation regression. Do not mark native conflict/re-registration PASS from source inspection. |
| Focus and optional paste | `SetForegroundWindow` is restricted; `SendInput` accepts only the correct INPUT structure size and cannot cross higher integrity levels under UIPI. Check target, generation, clipboard sequence and held modifiers; offer manual Ctrl+V. [Foreground API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow), [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) | Correct x64 INPUT union, no elevation workaround, no delayed repeated focus stealing. Plain copy remains the default. | Structure-size regression exists; real focus-switch, elevated target and distinct receiver scenarios remain separate tests. |
| Single instance and activation | Named `Global` objects span sessions; `Local` objects do not. Current mutex/event are scoped by Windows SID. Do not change to per-session mutex while sharing one on-disk profile. Publish the activation event before acquiring ownership and initialize a hidden autostart HWND without flashing history. [Kernel object namespaces](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces) | Keeps one writer per profile. A per-session UX would first require per-session storage or cross-process arbitration. | Immediate second launch, shutdown activation races and cross-session/RDP UX are not established by isolated smoke. |
| DPI and theme | Manifest declares PerMonitorV2; placement converts screen coordinates through the current device transform and clamps to a work area. Palette uses shared resources, Windows light/dark preference and high-contrast system brushes. [High DPI guidance](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) | No renderer replacement. A manifest alone does not fix mixed-DPI positioning or custom-template clipping. | Real 100/125/150/200% scales, monitor transitions, small working area and high contrast remain required before broad claims. |
| Tray lifecycle | Use a normal context menu, recognizable multi-size icon and explicit disposal. A notification-area icon may appear in overflow under user control. [Notification area](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area) | Existing WinForms NotifyIcon avoids a second custom shell implementation. Do not force visibility or nuisance notifications. | Explorer restart, sleep/resume, session lock/unlock and icon readability at small scales are not proven by code review. |
| Storage protection | DPAPI normally ties decryption to the same user and machine. Keep CurrentUser protection and bounded validation; describe backup portability accurately. [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) | No bespoke cryptography or password-vault claim. Same-user privileged processes and open clipboard remain outside this boundary. | Synthetic encryption, migration, validation and transaction recovery tests passed; UI recovery and external OS failures need separate acceptance. |
| Distribution | Keep x64 self-contained single-file with native library extraction. Disable trimming; WPF is not trim-compatible. [Single-file deployment](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview), [Trimming incompatibilities](https://learn.microsoft.com/en-us/dotnet/core/deploying/trimming/incompatibilities) | Larger file avoids runtime installation. NativeAOT, compression, MSIX and an updater add acceptance cost without a demonstrated need here. | First extraction, non-ASCII/space paths and a clean machine without desktop runtime require explicit tests. A developer-machine launch is insufficient. |
| Signing | Verify signature status instrumentally; sign before calculating the final hash if a real certificate becomes available. [SignTool](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool) | The candidate is unsigned; no certificate is purchased or simulated. Hash matching establishes file integrity, not publisher identity. | No promise to avoid SmartScreen. Never disable system protection as a distribution instruction. |

## Release consequences

The highest-value additions remain full-content search, a visible search reset, simple filters, a configurable hotkey and temporary pause. They reuse native controls and do not add a runtime framework, account, background network service or plugin execution engine. More features are not needed to resolve the remaining acceptance gaps.

The runtime decision is justified by support lifetime, not by an assumption that every operation becomes faster. The intermediate process measurements in [PROCESS-PERFORMANCE.md](PROCESS-PERFORMANCE.md) show a repeated-start regression alongside much lower model/search allocation in [STORAGE-REVIEW.md](STORAGE-REVIEW.md). Report both. Production idle, useful-input latency and final binary E2E remain independent evidence requirements.

Every URL above was opened during this review. API documentation establishes the Windows contract, not proof that the application meets it in every environment. Deferred checks must stay visible rather than being converted to PASS by a successful build.

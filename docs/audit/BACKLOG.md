# Приоритизированный backlog NeClipboard Win

Дата решения: 2026-10-11. Основание: [исследование 14 продуктов и 5 дополнений](RESEARCH.md), чтение исходного состояния 0.1.5 и обязательные критерии согласованного задания на аудит.

Это **список решений, а не список выполненных работ**. Фактическое выполнение, версия, результаты и ограничения фиксируются в [сводке приёмки](ACCEPTANCE.md) и профильных отчётах. Рекомендации research не подменяют независимую техническую проверку. Код параллельно меняется; «исходно» ниже относится к началу аудита.

P0 — блокирует достоверный публичный выпуск/сохранность; P1 — высокая польза/надёжность; P2 — следующий продуктовый этап; P3 — гипотеза. Трудоёмкость S/M/L означает маленькую/среднюю/крупную задачу, без обещания календарных сроков. Runtime: «нет» — новые постоянные runtime-зависимости не нужны, но конкретный эффект подтверждается измерением. Риск данных относится к **изменению**, а не объявляет текущую программу небезопасной.

## Конечный scope текущего цикла

Исправления сохранности, clean build/release и приватности; поддерживаемая LTS; bounded preview с полным поиском; заметная очистка поиска и временная пауза; необходимая UI/performance/backup/upgrade приёмка; EXE, Release, download validation, сайт и changelog. Ни один пункт «позже» не является обязательством реализовать весь набор конкурентов сейчас. Если проверка выявит новый блокирующий дефект, он входит в текущий scope независимо от списка.

### B01. Единая проверка входных history/settings/backup

- **Проблема / доказательство:** malformed или слишком крупный файл не должен приводить к безграничному чтению, молчаливой перезаписи и потере истории. Исходный `Persistence.cs` читает history/settings через `ReadAllBytes`; строгие backup limits не доказывают такую же защиту обычной загрузки.
- **Желаемое:** границы до чтения и после decrypt/deserialize, допустимые enum/null/строки/количество/байты, понятное восстановление повреждённого файла. Не затирать неизвестную будущую схему.
- **Решение:** сейчас; P0; M. Зависимости: общий формат/лимиты. Runtime: нет новых библиотек; риск данных высокий, нужны fixtures.
- **Приёмка:** реально oversized/null/invalid-enum/base64/current+previous corruption fixtures; рабочие данные не заменяются пустыми без сообщения; пик памяти ограничен.

### B02. Последовательность фоновых сохранений

- **Проблема / доказательство:** save/clear/restore/exit используют общие файлы; необходимо доказать отсутствие stale writes. Это задача проверки гонок, а не утверждение о воспроизведённой потере. См. `MainWindow.xaml.cs` save paths.
- **Желаемое:** один согласованный writer, ограниченная очередь/coalescing, понятный flush; после clear старый snapshot не возвращается.
- **Решение:** сейчас; P0; M. Зависимости B01. Runtime: уменьшить лишние IO, без framework; риск высокий.
- **Приёмка:** управляемая задержка записи + capture/clear/restore/exit; на рестарте совпадает последний разрешённый снимок, задачи завершаются без deadlock.

### B03. Согласованный backup snapshot

- **Проблема / доказательство:** `ToList()` копирует список, но не mutable entries/settings. Исходный `CreateBackupButton_Click` передаёт изменяемые объекты в async путь.
- **Желаемое:** snapshot с независимыми изменяемыми полями, сформированный согласованно; тяжёлая сериализация вне UI.
- **Решение:** сейчас; P0; M. Зависимости B01/B02. Runtime: bounded кратковременная память; риск средний.
- **Приёмка:** менять snippet, pin, настройки и добавлять entry во время backup; восстановленный документ внутренне согласован и соответствует выбранному snapshot, исходные данные не меняются.

### B04. Restore с проверяемым rollback

- **Проблема / доказательство:** восстановление меняет history/settings и native effects; две отдельные записи не являются транзакцией. Исходный restore требует ревью sync IO и результатов отката.
- **Желаемое:** validate-before-mutate, сериализация конкурентных действий, точное сообщение о результате каждого save/rollback.
- **Решение:** сейчас; P0; L. Зависимости B01–B03. Runtime: нет; риск высокий.
- **Приёмка:** отказ на каждом этапе применения/отката; либо старое целое состояние, либо явный recoverable результат. Не показывать «успешно», если rollback/save не удался.

### B05. Чистый CI без старых bin/obj

- **Проблема / доказательство:** исходное задание зафиксировало checkout после чтения csproj и `--no-build` отдельного не собранного test-проекта. Новый workflow уже меняется release-агентом, но его зелёный статус ещё нужно доказать.
- **Желаемое:** checkout→SDK→явная сборка verification→tests→publish→smoke; native exit code прерывает шаг.
- **Решение:** сейчас; P0; M. Зависимости B08. Runtime приложения: нет; риск низкий.
- **Приёмка:** изолированный чистый snapshot успешно собирается; при доступном repo проходит реальный GitHub runner на точном SHA; synthetic failing command не маскируется.

### B06. Проверенный SHA → draft → публичный asset

- **Проблема / доказательство:** tag/release должен относиться к проверенному commit; GitHub source archive не заменяет EXE. [Clipy Releases](https://github.com/Clipy/Clipy/releases) показывает разделение tags/assets/notes.
- **Желаемое:** строгий tag, explicit commit, minimum permissions, serialized releases; окончательный файл переносится без пересборки; опубликованную версию нельзя незаметно overwrite.
- **Решение:** сейчас; P0; M. Зависимости B05, доступ GitHub. Runtime: нет; риск поставки высокий.
- **Приёмка:** mismatch/existing tag/repeated version fail; draft проверен; public EXE без login имеет тот же version/hash/signature, что финальный локальный asset.

### B07. Проверка публикуемых Git blobs и секретов

- **Проблема / доказательство:** рабочий файл может отличаться от staged; исключения `.gitignore` не блокируют force-add. Исходный preflight сканировал ограниченные regex в рабочих файлах.
- **Желаемое:** exact index/history scan при наличии, запрет user data/certs/binaries вне допустимых assets, безопасные сообщения без значений секретов.
- **Решение:** сейчас; P0; M. Зависимости: Git snapshot. Runtime: нет; риск публикации высокий.
- **Приёмка:** staged `.env.local`, forbidden EXE и staged synthetic token при чистом worktree блокируют публикацию; безопасные fixture строки не требуют отключать весь сканер.

### B08. Поддерживаемый runtime и self-contained servicing

- **Проблема / доказательство:** .NET 8 EOS 2026-11-10; .NET10 LTS до 2028-11-14. [Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).
- **Желаемое:** минимальная миграция WPF на .NET10, фиксированный SDK/осознанная patch policy; конечному пользователю SDK не нужен.
- **Решение:** сейчас; P1; M. Зависимости toolchain. Runtime: новый встроенный runtime, размер/старт измерить; риск средний.
- **Приёмка:** clean build, storage fixtures и final EXE работают; self-contained проверен на доступной чистой системе без runtime либо этот уровень честно BLOCKED, не PASS.

### B09. Bounded preview и поиск по полному содержимому

- **Проблема / доказательство:** исходный Preview вычисляет полную normalized строку повторно. Сам исходный preview **не обрезан**; существующий missing-tail bug этим не доказан.
- **Желаемое:** короткий cached preview, полный поиск отдельно по payload/source/type без больших повторных lower/replace аллокаций; не потерять поиск в конце.
- **Решение:** сейчас; P1; M. Зависимости модели. Runtime: уменьшить аллокации без индекса/БД; риск низкий.
- **Приёмка:** Unicode/CRLF/500k-character tail, filenames, no-results; preview bounded, payload copy точный. Одинаковый before/after benchmark ≥30 наблюдений, документированная семантика пробелов.

### B10. Видимая очистка поиска и устойчивый selection

- **Проблема / доказательство:** Esc→clear и empty states уже существуют; мышью способ очистки менее заметен. [ClipAngel](https://sourceforge.net/projects/clip-angel/) документирует clear-filter indication.
- **Желаемое:** доступная clear button появляется при запросе, очищает filter, возвращает фокус; после refresh нет невидимого stale selection.
- **Решение:** сейчас; P1; S. Зависимости B09. Runtime: нет; риск низкий.
- **Приёмка:** mouse/keyboard clear, Esc, no-results→results, удаление выбранного; Automation name и обе темы; Delete в TextBox продолжает редактировать текст.

### B11. Временная пауза и честный статус capture

- **Проблема / доказательство:** indefinite pause полезна, но её легко забыть; обычное пустое состояние «скопируйте» вводит в заблуждение, когда capture выключен. Это вывод из текущего UX, не статистика спроса.
- **Желаемое:** pause 15/60 min и ручное resume; tray/window/empty state показывают реальное состояние и срок. Ручное выключение не отменяется таймером неожиданно.
- **Решение:** сейчас; P1; M. Зависимости согласованное settings state. Runtime: один лёгкий таймер только при паузе; риск privacy средний.
- **Приёмка:** synthetic copy не сохраняется во время паузы; elapsed timer/resume/sleep не вызывает ретроспективного захвата уже лежащего секрета; permanent disable остаётся disabled.

### B12. Реальный desktop E2E финального EXE

- **Проблема / доказательство:** существующий isolated smoke отключает clipboard/hotkey/tray, поэтому не доказывает основной сценарий.
- **Желаемое:** изолированная сессия или контролируемые синтетические действия в Notepad/Explorer/browser/ещё одном доступном input.
- **Решение:** сейчас; P0; M. Зависимости final EXE, desktop tools. Runtime: тестовые инструменты не входят в app; риск личных данных предотвращается изоляцией.
- **Приёмка:** copy→hotkey→search→copy→manual paste; files/image/snippets/backup/restore/restart. Недоступные операции BLOCKED/NOT RUN, не подмена HTML demo.

### B13. Negative storage и upgrade fixtures

- **Проблема / доказательство:** успешный round-trip не проверяет повреждение, отказ записи и миграцию. Clipy предупреждает о migration backup в [1.3.0](https://github.com/Clipy/Clipy/releases/tag/1.3.0).
- **Желаемое:** безопасные fixtures для 0.1.5→новая версия, torn file/read-only/foreign DPAPI/future schema и rollback.
- **Решение:** сейчас; P0; M. Зависимости B01–B04. Runtime: нет; риск тестируется только на synthetic data.
- **Приёмка:** явная матрица actual outcomes; previous recovery не возвращает очищенные данные; миграция идемпотентна; старый EXE не обещается читать новую схему без проверки.

### B14. Производительность и ресурсный plateau

- **Проблема / доказательство:** «быстро» нельзя доказать ощущением. Требование пользователя и профиль Preview.
- **Желаемое:** cold/warm start, search/capture latency, allocations, private bytes/handles, idle10min, цикл1000 и длительный прогон; bounded history.
- **Решение:** сейчас; P1; M. Зависимости B09/final build. Runtime: измерительные инструменты вне app; риск низкий.
- **Приёмка:** PERFORMANCE содержит среду, датасет, количество наблюдений и диапазон; p95 не из двух запусков, нет необъяснённого постоянного роста. Невыполненный soak помечен точно.

### B15. Темы, DPI и клавиатура как часть приёмки

- **Проблема / доказательство:** прежние пользовательские скриншоты показывали нечитабельный selected text; конкуренты тоже исправляют dark/DPI отдельно. [Ditto release](https://github.com/sabrogden/Ditto/releases/tag/3.25.113.0).
- **Желаемое:** system light/dark, high contrast, focus/disabled/error, минимум окна, tab order и доступные названия.
- **Решение:** сейчас; P1; M. Зависимости final UI. Runtime: общие ресурсы WPF, без visual framework; риск низкий.
- **Приёмка:** реальные или явно ограниченные проверки 100/125/150/200%, screen edge, короткий/длинный текст, keyboard-only core; screenshots содержат лишь synthetic content.

### B16. Согласованные версия, download, сайт и changelog

- **Проблема / доказательство:** пользователю нужен готовый EXE и правдивые функции. Сайт не должен показывать несуществующий download или концепт как screenshot.
- **Желаемое:** один external release manifest после final signing/hash; версия/размер/OS/arch/signature/limitations едины; настоящий screenshot; сайт обновляется после asset.
- **Решение:** сейчас; P0; M. Зависимости B06/B12, site access. Runtime app: нет; риск поставки средний.
- **Приёмка:** anonymous download с сайта/GitHub, hash+version совпадают, latest и versioned notes доступны, desktop/mobile без overflow. Deployment подтверждён сервисом/публичной страницей.

### B17. Чёткая граница backup и файлов

- **Проблема / доказательство:** DPAPI backup не универсален; file entries содержат пути, не содержимое файлов. Текущий текст UI говорит «резервная копия истории» без полной границы.
- **Желаемое:** короткое пояснение same Windows user/machine и того, что сами файлы не копируются; не обещать vault от всех процессов пользователя.
- **Решение:** сейчас; P1; S. Зависимости B03/B04. Runtime: нет; риск низкий.
- **Приёмка:** UI/README/PRIVACY согласованы с реальным форматом; foreign DPAPI возвращает понятную ошибку, исходные данные целы.

### B18. Privacy marker и исключённые приложения

- **Проблема / доказательство:** passwords нельзя считать обычной историей; [ClipAngel](https://sourceforge.net/projects/clip-angel/) и [Alfred](https://www.alfredapp.com/help/features/clipboard/) учитывают маркеры/исключения.
- **Желаемое:** проверить точные Windows marker formats, нормализацию process names, foreground race, pause; не выводить payload в логи.
- **Решение:** сейчас — подтвердить и исправить обнаруженное; P1; M. Зависимости Windows docs/E2E. Runtime: нет; privacy риск высокий.
- **Приёмка:** synthetic marked text и исключённый процесс отсутствуют в сохранённых history/backup; ошибка определения процесса имеет документированную политику.

### B19. Настраиваемая глобальная горячая клавиша

- **Проблема / доказательство:** фиксированная Ctrl+Shift+V может конфликтовать с app paste-plain. Настройка hotkey есть у [ClipboardFusion](https://www.clipboardfusion.com/Features/) и Alfred.
- **Желаемое:** один editor комбинации, проверка недопустимой/занятой, сохранение только успешной; старая регистрация восстанавливается при отказе.
- **Решение:** позже, ближайший небольшой выпуск; P1; M. Зависимости B02/settings schema. Runtime: нет; риск native integration средний.
- **Приёмка:** конфликт с synthetic process, cancel, restart, unregister/exit, смена раскладки; UI всегда показывает реально зарегистрированную клавишу.

### B20. Добавить приложение в исключения без ввода .exe

- **Проблема / доказательство:** сейчас нужен ручной список имён; люди не знают exe. [Paste exclusions](https://pasteapp.io/help/exclude-apps) показывает явный app-selection сценарий.
- **Желаемое:** выбрать приложение/предыдущее окно, показать имя и путь до добавления; не исключить сам NeClipboard случайно.
- **Решение:** позже; P2; M. Зависимости B18. Runtime: разовый process query; privacy риск средний.
- **Приёмка:** Unicode/exited/elevated process, case-insensitive duplicate; предыдущее содержимое не удаляется скрыто, новые synthetic clips игнорируются.

### B21. Сохранить запись истории как сниппет

- **Проблема / доказательство:** частый текст приходится вставлять в editor вручную. [Alfred snippets](https://www.alfredapp.com/help/features/snippets/) и Raycast имеют history→snippet.
- **Желаемое:** один пункт для text entry открывает существующий editor с content; человек задаёт название.
- **Решение:** позже; P2; S. Зависимости устойчивый snippet save. Runtime: нет; риск низкий.
- **Приёмка:** Unicode/multiline, cancel ничего не пишет, validation inline без циклических modal alerts, исходная история не меняется.

### B22. Поиск по сниппетам

- **Проблема / доказательство:** список snippets без фильтра хуже масштабируется; сценарий описан [Alfred](https://www.alfredapp.com/help/features/snippets/).
- **Желаемое:** простой title/content search, понятный no-results, сохранение selection после edit.
- **Решение:** позже; P2; S. Зависимости B09/B10. Runtime: bounded scan; риск низкий.
- **Приёмка:** 200 snippets, хвост content, кириллица, clear, изменение title при фильтре; p95 в принятом бюджете.

### B23. Фильтр типа и только закреплённые

- **Проблема / доказательство:** text/images/files смешаны; [Raycast clipboard](https://manual.raycast.com/clipboard-history) и ClipAngel используют type filters.
- **Желаемое:** один компактный control, сочетающийся с поиском; виден активный filter, clear возвращает полный список.
- **Решение:** позже; P2; S. Зависимости B09/B10. Runtime: нет; риск низкий.
- **Приёмка:** комбинации text+query/pin/empty, keyboard traversal и правильные disabled actions; controls не переполняют narrow window.

### B24. Preview по запросу

- **Проблема / доказательство:** короткого preview иногда недостаточно, чтобы выбрать похожие записи. [ClipClip](https://www.clipclip.com/) показывает preview как отдельную ценность.
- **Желаемое:** клавиша/кнопка раскрытия bounded text/image preview без WebView и внешних URL.
- **Решение:** позже; P2; M. Зависимости B01/B09. Runtime: lazy image decode с бюджетом; риск недоверенных данных средний.
- **Приёмка:** огромный/повреждённый payload не зависает и не выполняет код; Esc возвращает фокус; скрытие освобождает preview ресурсы.

### B25. Ограничение истории по возрасту

- **Проблема / доказательство:** count/bytes не выражают «не хранить старше недели». [Paste retention](https://pasteapp.io/help/control-history-retention) и Alfred.
- **Желаемое:** несколько понятных сроков, явные правила pinned; чистка при событии/запуске, без частого polling.
- **Решение:** позже; P2; M. Зависимости B02/B13. Runtime: разовая фильтрация; риск удаления высокий.
- **Приёмка:** UTC/DST/clock changes, pinned, backup, restart; предупреждение до удаления, удалённое не возвращается из prev/pending save.

### B26. Наглядный лимит по байтам и pinned policy

- **Проблема / доказательство:** max items уже включает pinned, но пользователь не видит общий payload quota; большое изображение может вытеснить много текста.
- **Желаемое:** краткий usage indicator в settings и ясное объяснение, что pin не обещает бесконечное хранение; без постоянного recount.
- **Решение:** позже; P2; S. Зависимости B01/B02. Runtime: cached counters; риск низкий.
- **Приёмка:** count/bytes после add/delete/pin/restore точны; достижение лимита объяснено, pinned не удаляется вопреки тексту UI.

### B27. Data-only импорт/экспорт сниппетов

- **Проблема / доказательство:** backup DPAPI не подходит для передачи подготовленных шаблонов. [Espanso packages](https://espanso.org/docs/packages/basics/) показывает ценность обмена, но может включать код.
- **Желаемое:** versioned JSON text-only, count/size bounds, preview импорта, стратегия duplicate title; явное предупреждение, что export не зашифрован.
- **Решение:** позже; P2; M. Зависимости B01/B21. Runtime: System.Text.Json; риск экспорта средний.
- **Приёмка:** malformed/oversized/future schema отвергаются до изменения; никакие scripts/placeholders не исполняются; cancel сохраняет исходные snippets.

### B28. Импорт Clipy XML

- **Проблема / доказательство:** пользователю аналога Clipy может быть нужен перенос собственных snippets. Наличие [Clipy](https://github.com/Clipy/Clipy) не доказывает актуальную совместимость всех XML-форматов.
- **Желаемое:** спецификация на безопасных fixtures, разрешённые узлы, DTD/external entities выключены, preservation whitespace.
- **Решение:** исследовать после B27; P3; M. Runtime: встроенный XML parser; риск средний.
- **Приёмка:** fixture реально экспортированной текущей/старой Clipy; title/content round-trip; entity expansion и huge input отклоняются. Не заявлять совместимость до теста.

### B29. Сохранение нескольких rich formats

- **Проблема / доказательство:** plain text теряет форматирование Word/web. [Ditto](https://ditto-cp.sourceforge.io/) и CopyQ сохраняют разные clipboard formats.
- **Желаемое:** изучить bounded envelope text+HTML/RTF без активного renderer, fallback plain text и миграцию schema.
- **Решение:** исследовать отдельно; P2; L. Зависимости B01–B04/B12. Runtime: рост payload/validation, оценить; риск высокий.
- **Приёмка:** copy from browser/office-like target сохраняет нужное; HTML не загружает сеть/скрипты; malformed RTF не ломает startup. Не включать PDF editor как скрытую часть.

### B30. Явная команда «Без форматирования»

- **Проблема / доказательство:** полезна только при наличии реально сохранённых rich formats; сейчас text entry уже plain. [Copy PlainText](https://addons.mozilla.org/en-US/firefox/addon/copy-plaintext/).
- **Желаемое:** отдельная secondary action после B29, без изменения original entry.
- **Решение:** позже при B29; P2; S. Runtime: нет отдельной библиотеки; риск низкий.
- **Приёмка:** styled source→plain paste без HTML/RTF; обычный copy оставляет оригинальные formats; действие не рекламируется как новая функция раньше B29.

### B31. Объединить выбранные текстовые записи

- **Проблема / доказательство:** иногда нужно вставить несколько строк разом. [Alfred merging](https://www.alfredapp.com/help/features/clipboard/) — пример соседнего сценария, но не точного нашего UI.
- **Желаемое:** явный multi-select join с preview порядка и разделителя; не последовательная эмуляция ввода.
- **Решение:** позже; P2; M. Зависимости B24. Runtime: bounded join; риск ошибочной вставки средний.
- **Приёмка:** порядок соответствует UI, mixed format disabled с объяснением, лимит итогового размера, нет автосендов Enter/Tab в другое приложение.

### B32. Локальные преобразования текста

- **Проблема / доказательство:** trim/case/remove extra blank lines есть у [ClipClip](https://www.clipclip.com/features), но избыточный каталог actions мешает core.
- **Желаемое:** проверить спрос на 2–3 явные операции как копирование нового результата, с undo/cancel до применения; не изменять history silently.
- **Решение:** исследовать; P3; M. Зависимости B24. Runtime: bounded string allocation; риск изменения содержания средний.
- **Приёмка:** Turkish casing/Unicode/CRLF/whitespace fixtures; original неизменён, результат предварительно виден; benchmark больших текстов.

### B33. Удалить недавние записи по интервалу

- **Проблема / доказательство:** случайно скопированное чувствительное можно убрать без clear-all. [Alfred](https://www.alfredapp.com/help/features/clipboard/) предлагает недавние интервалы.
- **Желаемое:** команда «последние15мин» с count/правилами pinned; очищать соответствующие snapshots/previous согласно обещанию.
- **Решение:** исследовать; P2; M. Зависимости B02/B25. Runtime: нет; риск удаления высокий.
- **Приёмка:** границы UTC, pinned, pending writes, restart; удалённое не восстанавливается скрыто. Не обещать secure erase SSD.

### B34. Автоматический password-pattern detector

- **Проблема / доказательство:** исключения процессов не покрывают секрет в обычном browser/editor; regex не может надёжно распознать все секреты.
- **Желаемое:** сначала threat model/false positives, явный opt-in лишь при доказанной пользе; markers/exclusions сохраняют приоритет.
- **Решение:** исследовать, не включать сейчас; P3; M. Зависимости B18. Runtime: bounded regex; риск ложной уверенности высокий.
- **Приёмка:** dataset synthetic secrets/nonsecrets, false positive/negative отчёт; UI не обещает гарантированное распознавание паролей.

### B35. Версия и ручная ссылка на обновления

- **Проблема / доказательство:** человек не знает свой build и куда сообщать баг; release chain требует точной версии.
- **Желаемое:** компактная About строка с assembly version, сайт и подтверждённый Releases URL, открываемый только по действию.
- **Решение:** позже либо внутри текущей документационной доработки без расширения; P2; S. Зависимости B16/реальный repo. Runtime: нулевой idle/network; риск низкий.
- **Приёмка:** версия из assembly, не дублируемая строка; offline app работает, кнопка не ведёт на placeholder, копирование diagnostics не включает clipboard.

### B36. Подпись издателя

- **Проблема / доказательство:** unsigned EXE может вызвать SmartScreen. [Ditto](https://github.com/sabrogden/Ditto) использует SignPath.
- **Желаемое:** выбрать применимый signing provider/сертификат, защитить key, timestamp, hash после подписи; без обещания автоматического исчезновения репутационных предупреждений.
- **Решение:** исследовать/подготовить; P1; M + внешняя зависимость. Runtime: нет; риск supply chain высокий.
- **Приёмка:** Authenticode Valid с правильным publisher, CI key недоступен PR; финальный signed asset заново проверен. Не покупать услугу/выдумывать identity.

### B37. WinGet manifest

- **Проблема / доказательство:** пользователи GitHub привыкли к обновлению пакетным менеджером; [Ditto](https://ditto-cp.sourceforge.io/) предлагает winget.
- **Желаемое:** после стабильного публичного release оформить проверяемый package manifest и корректный upgrade mechanism.
- **Решение:** позже; P2; M. Зависимости B06/B36 и применимый installer/portable policy. Runtime: нет; риск распространения средний.
- **Приёмка:** validation, install/upgrade/uninstall в чистой среде, SHA совпадает; не выдавать локальный manifest за принятый пакет.

### B38. Installer/MSIX как дополнительный путь

- **Проблема / доказательство:** перенос EXE ломает путь autostart; installer может дать устойчивый путь/удаление. Это гипотеза удобства, не повод отменять download→run.
- **Желаемое:** оценить per-user install без admin, signing/update/rollback и размер; portable сохранить.
- **Решение:** исследовать после стабильного portable; P3; L. Зависимости B36. Runtime: небольшой packaging overhead; риск данных средний.
- **Приёмка:** install/update/uninstall сохраняют обещанные данные, autostart согласован, отмена чиста; нет обязательного dev runtime.

### B39. Native ARM64 выпуск

- **Проблема / доказательство:** ARM Windows — отдельная архитектура; runtime может поддерживать её, но это не доказательство app compatibility.
- **Желаемое:** отдельный RID/build/asset/site button и native test machine.
- **Решение:** исследовать при доступной системе; P2; M. Зависимости B05/B12/B16. Runtime: отдельный файл; риск compatibility средний.
- **Приёмка:** native ARM64 запуск/clipboard/hotkey/storage/E2E; x64 emulation не считается native PASS; без теста поддержку не заявлять.

### B40. Истинный portable data-directory

- **Проблема / доказательство:** portable EXE и переносимые данные — разные свойства; DPAPI history рядом с EXE не становится межмашинной.
- **Желаемое:** отдельно решить, нужен ли выбор data directory, угрозы USB/network path/permissions/second instance.
- **Решение:** отложить исследование; P3; M. Зависимости B01/B38. Runtime: нет; риск данных высокий.
- **Приёмка:** понятная привязка DPAPI, недоступный/readonly путь не теряет history, single-instance изолирован по профилю без конфликтов listener.

### B41. Переносимый зашифрованный backup с паролем

- **Проблема / доказательство:** нынешний DPAPI backup неудобен при смене компьютера; это отдельный сценарий от надёжного local restore.
- **Желаемое:** исследовать authenticated encryption/KDF поддерживаемой библиотеки, format version, UX пароля и recovery; никакой самодельной криптографии.
- **Решение:** исследовать; P2; L. Зависимости B01–B04. Runtime: стоимость KDF/библиотеки измерить; риск высокий.
- **Приёмка:** wrong password/tamper/truncation/size limits, независимый crypto review и межмашинный тест; не создавать plaintext промежуточный файл.

### B42. Английская локализация

- **Проблема / доказательство:** публичный GitHub даёт международную аудиторию; сейчас тексты русские.
- **Желаемое:** RU/EN ресурсы и auto language со стабильным fallback; не переписать UI ради localization framework.
- **Решение:** позже; P2; M. Зависимости B15/B16. Runtime: resource strings; риск низкий.
- **Приёмка:** обе локали без hardcoded key strings, длинный перевод при200%DPI, status/accessibility translated, hotkey соответствует настройке.

### B43. Диагностика для Issues без содержимого clipboard

- **Проблема / доказательство:** без version/OS/steps баг плохо воспроизводится; dump/log может раскрыть секреты.
- **Желаемое:** шаблон Issues и opt-in copy diagnostics: version/OS/arch/theme/error code/size counters; никакого payload/личных путей.
- **Решение:** позже; P2; S. Зависимости B35/B07. Runtime: по запросу; privacy риск средний.
- **Приёмка:** synthetic unique secret/path не встречаются в diagnostics; preview перед копированием, нет фонового upload; private security link существует.

### B44. PNG-кодирование вне долгой UI-блокировки

- **Проблема / доказательство:** исходный CaptureClipboard кодирует image на UI; величину задержки нужно измерить, а не считать любое Task.Run улучшением.
- **Желаемое:** STA clipboard access остаётся допустимым; frozen copy перед worker, latest sequence/version guards и bounded queue.
- **Решение:** исследовать в текущем профиле; если подтверждена блокировка core — исправить сейчас; P1; M. Зависимости B14/B18. Runtime: потенциальное снижение UI latency, extra bitmap memory bounded; риск средний.
- **Приёмка:** transparency/DPI/oversize/rapid-change, no stale capture после pause/clear; UI delay и peak memory до/после; никаких COM clipboard calls в произвольном worker.

### B45. Browser citation integration

- **Проблема / доказательство:** text clipboard не всегда содержит page title+source URL; [Copy as Markdown](https://github.com/yorkxin/copy-as-markdown) это решает.
- **Желаемое:** сначала гарантировать точное сохранение готового Markdown; собственное расширение только после доказательства недостижимого стандартным clipboard сценария.
- **Решение:** исследовать позже; P3; L при native messaging. Зависимости B27/B18. Runtime: отдельный optional компонент; privacy риск высокий.
- **Приёмка:** user gesture, минимальные permissions, отсутствие all-sites default, bounded messages и origin allowlist; app полезен без extension.

### B46. Встроенный scripting/plugins marketplace

- **Проблема / доказательство:** CopyQ/ClipboardFusion/Espanso расширяемы, но исполняемый код из plugins добавляет supply-chain и поддержку API.
- **Желаемое для core:** данные остаются данными; небольшие встроенные actions предпочтительнее универсального runtime.
- **Решение:** отклонить текущую продуктовую линию; P3; L. Runtime: существенная новая ответственность; риск высокий.
- **Критерий пересмотра:** конкретный недостижимый сценарий, модель разрешений/sandbox/update trust, стоимость сопровождения и отдельное решение владельца; наличие функции у конкурента недостаточно.

### B47. Облачная синхронизация/аккаунты

- **Проблема / доказательство:** [1Clipboard](https://1clipboard.io/) использует Google Drive; спрос на multi-device возможен, но меняет локальную модель приватности.
- **Желаемое для текущего продукта:** работа без аккаунта/сети и понятный local backup.
- **Решение:** отклонить текущий scope; P3; L. Runtime: сеть/auth/storage/операционные расходы; риск утечки высокий.
- **Критерий пересмотра:** пользовательский спрос, отдельное разрешение, E2E encryption/key/recovery design, бюджет и тесты конфликтов; не вводить ради parity.

### B48. AI/OCR/MCP всей истории

- **Проблема / доказательство:** Paste/Raycast предлагают смежные функции, но автоматическая обработка всего clipboard увеличивает CPU и область доступа к приватным данным.
- **Желаемое для текущего продукта:** отсутствие фонового анализа/выгрузки. OCR по явно выбранной картинке можно исследовать отдельно позже.
- **Решение:** отклонить текущий scope; P3; L. Runtime: модели/службы/сеть потенциально велики; privacy риск высокий.
- **Критерий пересмотра:** один явный opt-in сценарий, local API feasibility, bounded cost, permissions, отключённый default; никогда не давать агенту всю историю автоматически.

### B49. Единая сущность tags/folders/profiles/workspaces

- **Проблема / доказательство:** CopyQ/ClipClip/Alfred предлагают разные способы организации, но добавление всех одновременно усложняет простой popup.
- **Желаемое сейчас:** история + pin + snippets; при реальном росте выбрать один дополнительный способ организации.
- **Решение:** отклонить одновременное внедрение; P3; L. Runtime: индексы/UI/state; риск миграций средний.
- **Критерий пересмотра:** наблюдаемые сценарии большой коллекции, prototype и usability test; доказать отличие выбранной сущности от существующего pin/snippets.

### B50. Автообновление EXE

- **Проблема / доказательство:** удобство обновления требует защиты от подмены/downgrade и сохранения данных; это существенно больше открытия URL.
- **Желаемое сейчас:** ручной переход к подтверждённому Release. Автообновление — отдельная будущая спецификация, не функция этого выпуска.
- **Решение:** отклонить реализацию в текущем scope; P3; L. Зависимости B06/B36. Runtime: updater network/rollback; риск высокий.
- **Критерий пересмотра:** authenticity/version validation, opt-in, отсутствие privileged service, testable crash recovery и rollback; пользователь видит доступную версию и управляет установкой.

### B51. Отмена удаления записи

- **Проблема / доказательство:** случайное Delete неприятно, но незаметная «корзина» сохраняет содержимое вопреки ожиданию удаления приватной истории.
- **Желаемое:** сначала определить простую политику undo отдельной записи, отличную от безвозвратного Clear, и понятный короткий срок хранения.
- **Решение:** исследовать позже; P3; M. Зависимости B02/B33. Runtime: bounded in-memory retained item; privacy риск высокий.
- **Приёмка:** UI явно сообщает срок отмены; Clear/Exit уничтожают undo-состояние по контракту, старые pending writes не возвращают запись, никаких скрытых долгоживущих disk snapshots.

## Почему выбран именно такой порядок

B01–B08 предотвращают выпуск неподтверждённого/ненадёжного дистрибутива. B09–B11 дают ежедневную пользу без framework и роста роли приложения. B12–B18 обеспечивают проверку фактического поведения и согласованную передачу пользователю. Среди следующего набора B19/B21/B23 имеют понятные частые сценарии, а B27 решает обмен шаблонами без accounts. Rich text, переносимые backup и ARM64 требуют своих испытаний. Отклонённые идеи не делают core быстрее или проще сами по себе.

Новые библиотеки в принятом малом scope не требуются. Рефакторинг выполняется только там, где нужен отдельный проверяемый контракт (валидация, очередь сохранения, snapshot), без внедрения тяжёлого framework. Изменение runtime не равно смене UI-архитектуры.

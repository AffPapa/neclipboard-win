## Подтверждённые проблемы

### UI-01 — P1: primary-кнопки теряют читаемость при наведении/нажатии

- Участок: `MainWindow.xaml`, общий `Button` template, первоначально строки 30–31; `PrimaryButton`, 39–42; палитры `ThemeManager.cs`.
- Причина: общий template заменяет фон на `HoverBrush` / `PressedBrush`, но primary-стиль оставляет `Foreground=AccentTextBrush`.
- В светлой теме получается белый текст на `#EAF1F5` (контраст **1.14:1**) / `#DCE8EE` (**1.25:1**). В тёмной — `#062D29` на `#243039` (**1.10:1**) / `#11191D` (**1.20:1**). Числа рассчитаны из sRGB-палитры, а не оценены по скриншоту.
- Затрагивает основные действия: копирование/вставка и сохранение. High Contrast тоже нельзя считать исправленным, если `HighlightTextBrush` помещён на `WindowBrush` без проверки пары цветов.
- Происхождение: общая проблема шаблона, сохранившаяся в текущем дереве; не объявляется доказанной новой регрессией.
- Исправление: отдельные согласованные accent hover/pressed пары либо смена foreground на обычный текст при смене фона. Нужна проверка тем и disabled/focus состояний.
- Acceptance: текст всех primary-кнопок читается в normal/hover/pressed/focused для light, dark и системного High Contrast; небольшой текст имеет контраст не ниже 4.5:1. Скриншоты именно hover/pressed, не только обычного окна.

### UI-02 — P1: после неуспешного завершения паузы интерфейс сообщает о паузе, но захват уже разрешён

- Участок: `IsCaptureActive`, `PauseTimer_Tick`, `SaveSettingsAsync`; первоначально строки 778, 799–810, 846–858.
- Последовательность: дедлайн `CapturePausedUntilUtc` истёк → вычисляемое `IsCaptureActive` уже `true` → timer остановлен → сохранение очищенного дедлайна завершается `false` → `UpdateCaptureState` не вызывается и timer не перезапускается.
- Следствие: заголовок/кнопка/трей могут неограниченно показывать «Пауза до…» / «Продолжить», при этом следующие clipboard updates записываются. Ошибка диска или ACL превращается в неверное обещание приватности.
- Происхождение: новая функциональность timed pause.
- Исправление: единая модель фактического состояния и визуального индикатора. Предпочтительно fail-closed при незавершённом переходе с понятной ошибкой; либо явно и синхронно отображать возобновлённый захват даже при ошибке persistence. Нельзя оставлять ложный индикатор паузы.
- Acceptance: fault injection `TrySave=false` при истечении таймера; состояние кнопки, трея, empty state и фактический захват совпадает. Дополнительно проверить истечение во время backup/restore/save и после сна.

### UI-03 — P1: ошибка последнего сохранения не отменяет завершение приложения

- Участок: `DrainHistorySavesAsync` / `ExitApplication`; первоначально строки 672–674 и 1074–1090.
- Причина: неуспешный `TrySave` только пишет status, а публичный save task не возвращает результат. `ExitApplication` после await всегда уничтожает окно и процесс.
- Следствие: последние несохранённые записи/изменения теряются; короткоживущее сообщение в скрытом tray-окне пользователь не видит. Возможные причины — заполненный диск, отказ доступа, заблокированный файл.
- Происхождение: сохранённый из baseline путь, не новая доказанная регрессия.
- Исправление: результат итогового flush должен участвовать в решении о выходе. При ошибке — оставить данные в памяти и видимую возможность повторить/экспортировать/явно выйти без сохранения. Не создавать бесконечный неотменяемый retry.
- Acceptance: искусственный отказ final flush не приводит к молчаливому выходу; повтор после снятия отказа сохраняет последний snapshot. Отдельно проверить уже выполняющийся save + немедленный Exit.

### UI-04 — P1: отложенная автоподстановка не привязана к конкретной операции/содержимому

- Участок: `PasteEntry`, первоначально строки 388–404.
- Причина: callback через 120 + 50 мс хранит только target HWND. Перед `SendPasteShortcut` нет проверки clipboard sequence, generation текущей операции или `_exiting`. Он сам возвращает старое окно на передний план, а затем проверяет, что это окно активно.
- Последовательность: выбрали A → за задержку скопировали B или выбрали второй элемент → старый callback вставляет текущий B в старую цель; два callback могут дать двойную вставку. Переход пользователя в другую программу за первые 120 мс также не отменяет принудительный возврат старой цели.
- Риск: не то содержимое / не тот ожидаемый пользователем контекст. Feature экспериментальная и выключена по умолчанию, но это не устраняет ошибку для включившего её пользователя.
- Происхождение: оставшаяся проблема исходного delayed-paste пути.
- Исправление: идентификатор операции, локально захваченная sequence, отмена при следующем выборе/закрытии/смене clipboard; проверять контекст перед активацией и непосредственно перед SendInput. При сомнении оставить только безопасное копирование и честный status.
- Acceptance: изменение clipboard, быстрое повторное действие, переключение foreground и Exit во время задержки не дают старой/двойной/чужой вставки. Успешный случай вставляет ровно один выбранный элемент. Elevated target не обходит UIPI.

### UI-05 — P2: пока завершается final flush, доступны мутации, которые уже не будут сохранены

- Участок: `ExitApplication`, `UpdateActionState`, `PinButton_Click`, `DeleteButton_Click`, `PasteSelectedEntry`, `ScheduleHistorySave`; первоначально строки 413–429, 640, 679–696, 1070–1074.
- Причина: выход выставляет `_exiting=true`, но не блокирует UI. Pin/Delete/Paste проверяют `_storageBusy`, а не `_exiting`. При этом `ScheduleHistorySave` уже отказывается планировать запись.
- Следствие: пользователь успевает изменить модель после взятия финального snapshot на медленном диске; интерфейс показывает успех, но изменение не переживёт закрытие.
- Исправление: после начала выхода заблокировать входы мутаций/повторные paste, не подменяя этим `_storageBusy` так, чтобы final flush был пропущен; при отмене выхода вернуть рабочее состояние.
- Acceptance: замедленный финальный save; клики/клавиши/трей во время выхода не изменяют snapshot незаметно. Повторный Exit идемпотентен.

### UI-06 — P2: timer паузы и другие несвязанные сохранения стирают черновик настроек

- Участок: `SaveSettingsAsync` всегда вызывает `LoadSettingsControls`; первоначально строки 853 и 868–879.
- Последовательность: пользователь редактирует лимит, exclusions, автозапуск или новое сочетание, ещё не нажал «Сохранить» → истекает пауза либо нажата верхняя кнопка паузы → сохранение клона текущих persisted settings перезаполняет все controls.
- Следствие: введённые настройки бесшумно потеряны. При выборе нового hotkey сбрасывается также `_pendingHotkeyModifiers/_pendingHotkeyKey`.
- Происхождение: новый единый async helper усиливает coupling разных действий.
- Исправление: отделить draft настроек от persisted settings; после timed pause обновлять только capture UI, а все поля загружать при явном применении/отмене/restore.
- Acceptance: несохранённый черновик остаётся при pause/resume/expiry и работе со сниппетом; успешный Save/Restore обновляет его намеренно.

### UI-07 — P2: один путь отката native-настроек скрывает собственную ошибку

- Участок: `SaveSettingsAsync` при `TryApplyNativeSettings=false` и предварительный restore-check; первоначально строки 840–844 и 522–526.
- Причина: `TryApplyNativeSettings` сначала может зарегистрировать новый hotkey и освободить старый, затем упасть на автозапуске. Вызванный после этого откат `TryApplyNativeSettings(previous, out _)` проверяется не во всех ветках.
- Следствие: если прежнее сочетание уже занято или rollback registry тоже не прошёл, status обещает «Настройки не применены», хотя native state может отличаться от `_settings` и значка hotkey. Путь отказа сохранения файла уже проверяет rollback, но предварительный native-failure путь — нет.
- Происхождение: новые транзакционные native settings.
- Исправление: учитывать результат отката на всех путях; желательно отделить apply/rollback hotkey и registry, сохраняя фактическое состояние и сообщая о частичной ошибке.
- Acceptance: fault injection на втором шаге apply и на rollback; UI не утверждает гарантированный откат, если он не состоялся; доступен путь восстановить рабочую клавишу.

### UI-08 — P2: сохранение обычных настроек требует записи в Run даже без изменения автозапуска

- Участок: `TryApplyNativeSettings` → `ConfigureStartup`; первоначально строки 911 и 723–732.
- Причина: любое «Сохранить» вызывает `CreateSubKey(...Run, true)` и Set/DeleteValue, даже если `LaunchAtSignIn` не изменён.
- Следствие: в ограниченной политиками среде нельзя сохранить лимит истории/исключения/другие локальные настройки из-за запрета unrelated записи Run. Также лишний syscall/реестровая мутация при каждом save.
- Исправление: применять системные изменения только при необходимости, сравнивая фактическое/предыдущее состояние и намерение пользователя; explicit Restore может иметь отдельную стратегию reconciliation.
- Acceptance: при неизменном выключенном автозапуске и запрете записи Run обычные локальные настройки сохраняются; явное изменение автозапуска сообщает отказ честно.

## Дополнительные риски для проверки, не засчитанные как подтверждённые defects

1. **Несколько мониторов, разный DPI, маленькая рабочая область.** `ShowPalette` преобразует рабочую область монитора курсора через transform текущего HWND, затем только двигает окно, но не ограничивает размеры. На другом DPI преобразование может быть неверным; окно высотой 680 DIP может не поместиться в ~540 DIP рабочей области при 200%. Нужны реальный mixed-DPI тест и проверка сохранённого maximized/normal положения. Статический риск не равен доказанному дефекту в текущей конфигурации машины.
2. **Начатый до паузы image encode, затем pause→resume до завершения.** Epoch меняется для clear/restore/exit, но не для короткой паузы. Если изображение всё ещё тот же clipboard sequence, оно может быть принято после быстрого resume. Нужно явно определить продуктовый контракт: только «не собирать во время паузы» либо также «отменять все операции, начатые до паузы». Без согласованного контракта не считаем это подтверждённой ошибкой.

## Минимальный повторный QA после исправлений

- Изолированное хранилище и синтетический clipboard; ни один failure-test не должен ломать реальные данные пользователя.
- Light/dark: normal + hover + pressed + disabled + keyboard focus основных кнопок; затем реальный High Contrast.
- Timed pause: успешное истечение, отказ settings write, busy save/backup в момент истечения, sleep/resume.
- Delayed paste: normal, второй выбор, смена clipboard, смена foreground, Exit, elevated target. Зафиксировать, что безопасный отказ оставляет понятный статус и не посылает лишние клавиши.
- Final flush: успешный быстрый/медленный, отказ доступа, retry, отсутствие поздних мутаций.
- Hotkey: свободный, занятый, rollback после registry-failure, rollback-failure с честным сообщением. Не оставлять системные настройки QA после теста.
- Draft settings: ввести значения без Save, инициировать таймер/паузу, убедиться, что draft не сброшен.
- 100/150/200% DPI и разные мониторы: кнопки и статус доступны, окно не уезжает за рабочую область.

Исправления, которые появятся после этого снимка, должны получить отдельную запись о повторном чтении/тестировании. Нельзя автоматически преобразовать `found` в `verified fixed` только потому, что основной разработчик сообщил об изменении.

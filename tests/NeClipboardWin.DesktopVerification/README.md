# Native desktop verification fixture

Это отдельное Windows Forms test-приложение, не часть дистрибутива NeClipboard. Оно не отправляет клавиши и не управляет другими окнами: действия выполняет человек либо основной desktop automation agent. Fixture публикует только фиксированный синтетический текст, 2×2 RGB-изображение и два тестовых пути; служит реальным текстовым получателем и проверяет результат.

## Запуск

Создайте случайную папку `%TEMP%\NeClipboardWin-QA-<id>`. Оба EXE получают один и тот же каталог:

```powershell
# Приложение: реальные clipboard/hotkey/paste, временные данные, без реестра автозапуска.
.\NeClipboardWin.exe --qa-desktop "$qaDirectory"

# Fixture: UI с синтетическими источниками и полем-получателем.
.\NeClipboardWin.DesktopVerification.exe "$qaDirectory"
```

Для development apphost нужен .NET 10 Windows Desktop runtime; для автономной тестовой сборки:

```powershell
dotnet publish tests/NeClipboardWin.DesktopVerification/NeClipboardWin.DesktopVerification.csproj `
  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/desktop-fixture
```

Запускайте именно fixture `.exe`, а не `dotnet fixture.dll`: QA source allowlist опирается на имя процесса `NeClipboardWin.DesktopVerification.exe`.

Desktop QA принимает capture только от fixture-процесса, с точным custom marker `NeClipboardWin.SyntheticQa = UTF8("NeClipboardWin-QA")`, prefix текста, путями внутри временной `fixtures` и размером изображения 2×2. Автовставка разрешена только в окна fixture-процесса. Чужие clipboard payload в историю этого режима не принимаются; работа с системным clipboard всё равно общая для Windows-сеанса.

## Сохранность текущего clipboard

«Начать безопасный тест» копирует поддерживаемые текущие форматы исключительно в RAM. Неизвестный формат, неподдерживаемый тип, превышение 64 MiB общей копии или изменение sequence во время копирования приводят к отказу без изменения буфера. Никакой исходный текст, путь, пиксели или hash личного содержимого в журнал не попадают.

Не очищайте неизвестные форматы, чтобы обойти этот отказ. В таком окружении native test имеет статус BLOCKED до безопасной тестовой сессии. После начала не завершайте fixture через kill: закройте кнопкой «Вернуть буфер и закрыть» или обычным закрытием окна, чтобы выполнить возврат RAM-снимка.

При закрытии исходный буфер возвращается только если Windows sequence по-прежнему соответствует последней собственной либо успешно проверенной синтетической записи. Более новое стороннее копирование не перезаписывается. Публикация следующего тестового payload также отказывается перезаписывать неизвестное новое содержимое.

## Сценарии

### Безопасная диагностика снимка

CLI-режимы fixture без GUI и записи в системный буфер:

- `--inspect-clipboard-formats`: ограниченный список названий, без чтения значений.
- `--inspect-known-format-types`: только CLR-типы четырёх известных форматов и длина privacy-буферов; содержимое не выводится.
- `--inspect-native-format-storage`: только наличие нативных handles и ограниченная длина HGLOBAL; handles и байты не выводятся.
- `--snapshot-format-selftest`: in-memory проверка известных alias/DWORD, отказа неизвестным/повреждённым форматам и ownership/replay gates (включая одноразовый PASS), без доступа к clipboard.

Если WinExe не показывает stdout, чистую самопроверку можно выполнить через `dotnet NeClipboardWin.DesktopVerification.dll --snapshot-format-selftest`. Это исключение только для in-memory CLI; GUI fixture запускайте через EXE, как указано выше.

Снимок поддерживает точный alias `System.Drawing.Bitmap` и три Windows privacy DWORD. Значения флагов не меняются; требуется int либо ровно четыре байта. Наличие имени формата не доказывает доступность содержимого: если bitmap возвращается null, Begin отказывается без записи. Не пропускайте такой формат молча и не ослабляйте ограничения ради PASS.

1. Нажать «Начать безопасный тест». Убедиться, что снимок разрешён и тестовые кнопки стали доступны.
2. Нажать «1. Текст → буфер». Подождать появления синтетической записи в NeClipboard.
3. Нажать **«Контрольный текст перед вставкой»**. Fixture записывает другой фиксированный синтетический текст, без `Clipboard.Clear`. Шаг разрешён только при владении текущей sequence; после записи подтверждаются точный sentinel, отсутствие изображения/списка файлов и стабильная sequence. Только затем проверка считается подготовленной. Это обязательный шаг: иначе результат мог бы относиться к первоначальному payload, а не к воспроизведению из истории.
4. Из поля-получателя открыть NeClipboard через hotkey. Найти `tail-search-token`, выбрать текст и скопировать. Вставить в fixture через Ctrl+V. Нажать «Проверить вставленный текст»: точное содержимое clipboard и все символы поля-получателя (с нормализацией переносов строк), Unicode и переносы должны дать PASS. Нужна новая ненулевая sequence после подтверждённого sentinel; неизменённый контрольный текст всегда FAIL.
5. Для второго прохода включить автовставку только в изолированном QA-профиле NeClipboard. Повторить публикацию, контрольный текст, hotkey и выбор. Текст должен попасть в поле fixture без отдельного Ctrl+V; снова проверить кнопкой. Не меняйте настройки рабочего профиля ради теста.
6. Для изображения и файлов повторить **publish → дождаться capture → контрольный текст → открыть историю → выбрать сохранённую запись → verify**. Изображение проверяется по четырём точным RGB-пикселям, файлы — по обоим полным синтетическим путям. Это не проверка alpha-канала произвольных изображений. Все проверки требуют подтверждённого sentinel и новой стабильной sequence; PASS расходует подготовку, повторная проверка без нового sentinel не проходит.
7. Проверить конфликт hotkey: выбрать Ctrl+Alt+F9 в настройках NeClipboard, не сохранять; в fixture занять это сочетание соответствующей кнопкой; сохранить в NeClipboard. Должны появиться понятный отказ и сохраниться прежняя рабочая клавиша. Освободить тестовое сочетание кнопкой fixture.
8. Закрыть fixture штатно. Проверить, что журнал сообщает восстановление исходного clipboard или осознанный пропуск из-за более новой sequence.

Для дополнительной проверки только синтетического профиля:

```powershell
dotnet run --project tests/NeClipboardWin.Verification/NeClipboardWin.Verification.csproj `
  -c Release -- --inspect-desktop-qa "$qaDirectory"
```

Команда выводит количество типов и boolean проверки источника/prefix без payload. `desktop-fixture-results.log` внутри QA-каталога содержит только время, фиксированное имя теста и PASS/FAIL. Наличие fixture или успешная его сборка не являются результатом E2E; реальные действия, версии EXE и результаты должен зафиксировать выполнявший тест агент.

Ограничения: это не проверка Блокнота/Проводника/других настоящих получателей, повышенных процессов, RDP, multi-monitor или многопользовательской сессии. Такие сценарии выполняются отдельно при наличии безопасной среды. Проверка sequence и последующая WinForms-запись не образуют атомарную транзакцию с другими приложениями: guards отказывают при обнаруженном стороннем изменении, но не доказывают защиту от копирования строго одновременно с записью fixture. Проводите desktop E2E в коротком интервале без параллельного копирования.
